### 产品目标与优先级

核心目标：以精简、可追溯、可纠正的课程上下文，把连续课堂转成可执行的复习题案。先完成课程上下文、课堂分区分析、知识点分析、合并题案及复习计划；用户已确认分区/全课 QA 放在这条主线完成之后。图像理解作为后续增强，不阻塞文字主线。

课程是跨课堂的长期学习范围；课堂区间按授课过程组织；知识点与区间允许多对多关联。一个知识点跨两个区间时，合并为同一复习对象，同时保留不同讲解/例子及各自来源。课程改名不能丢关联，课程身份不能仅依赖分类标签或名称。

### 上下文的最小结构

| 层次 | 内容 | 约束 |
| --- | --- | --- |
| 课程卡片 | 用户课程背景、目标、章节结构、术语/符号约定、先修关系 | 从精简内容起步；不承诺固定字数可承载所有细节；重要更新展示依据并经用户确认 |
| 课程知识索引 | 已授知识点与课堂/原文位置的关联 | 原始课堂资料保留本地，按任务选择必要历史片段；不把不断压缩的摘要当作唯一依据 |
| 本课导览 | 整课目标、主题区间、知识点关系 | 局部分析保留本课全貌；覆盖不完整须明确标记 |
| 学习状态 | 建议复习日期与已复习状态 | 与课程知识分开；“已复习”不能推断为“学生掌握” |

### 一键分析与复习流程

1. 读取已结束课堂的最终转写、疑问/注释和板书位置，明确本次分析范围及上传同意；首版优先文字。
2. 结合课程卡片通读本课，按语义划区，给出全课导览、各区间主题、候选知识点和关联；保留原文定位，不机械按固定时长切分，不无提示截断。
3. 按知识点聚合相关区间，分析时提供精简课程卡片、本课导览、相关原文及必要历史依据。分析任务逻辑独立，不要求一个知识点固定对应一次供应商网络请求。
4. 生成学习单元：解释、适用条件、课堂重点；原文有例子才引用，没有则省略。提供可点击原文和板书索引，不强制易混淆/长篇依据。局部失败保留成功结果，仅重试失败或缺失阶段。
5. 合并为完整复习方案：知识点去重、合理排序，复习动作覆盖所有单元，引用始终可回到原始课堂。
6. 同次生成简单建议日期；首页列出待复习课堂，学生点入并标记“已复习”后移出待办，保留复习材料。
7. 原文或课程上下文更正后提示资料过期，重新分析保留旧版本；只预留区间/全课问答范围，不实现问答或自动改写课程事实。

题案回答“学什么、怎么复习、先做什么”，建议日期回答“哪天回看”。首页只显示待复习项与建议日期，不推算掌握率或增加期限/重要度表单。

## 以下为 V1 历史基线与 DSH 原实施范围

## 目标与验收结果

将现有课堂记录转成「有依据的知识总结 → 小测验证 → 可执行复习任务 → 答题后调整」的单节课闭环。建议参赛名：ClassMemory AI，中文副标题「从课堂记忆到个性化复习」。优先考虑 OPC 工具与超级个体知识服务方向，最终以报名系统分类为准。

验收演示：打开一节已结束的示例课堂，主动授权文字分析，生成带原文定位的知识卡片；选择每天可用分钟数和复习期限；完成 3–5 道单选题；故意错答一道，看到对应知识点的下一次复习任务发生变化；重开应用结果仍在。原课堂转写、疑问、注释不被 AI 覆盖。

关键产品原则：提问、笔记少、转写缺失都不能直接证明学习薄弱。首次分析只输出「待验证知识点」；诊断必须展示依据，答题次数不足时显示「证据不足」，不用伪精确的掌握率。用户始终可以修改计划。

## 产品流程与 AI 边界

1. 仅已结束且存在最终转写的课堂可分析。首次说明将发送的文字范围，允许预览/排除片段；默认不发送音频、图片、设备身份或私人课表。
2. 四项固定 Skill 是版本化的任务模板和输入输出校验器，不是通用自主执行框架：Summary 总结、Knowledge 提取知识和待验证点、Quiz 出题、Planning 安排复习。
3. 首次一键操作优先合并成一次结构化模型请求，返回总结/知识点/题目；Planning 使用本地时间约束生成任务，避免四个 Skill 固定串行调用四次。需要重新出题时才额外请求。
4. 首版只做单选题，本地比对标准答案；答错将该知识点设为待复习，安排「回看原文 → 解释概念 → 再测」，答对仅记录一次成功证据。自主声明的疑问提高验证优先级，不直接判错。
5. 推荐间隔作为可解释的工程规则：错答后下一可用时段优先、再次答对后可移到后续日期；不能承诺科学诊断或效果提升。任务拥挤时延期并说明原因，不偷偷超出用户时间预算。
6. 展示 pending/running/succeeded/failed/cancelled；同课堂同内容重复点击不重复请求；用户取消后不落入成功态。失败保留上次有效结果，用户主动重试，无后台无限重试。

## 实现切片与数据合约（均为拟新增）

路径以 `class-memory/android/app/src/main/java/com/classmemory/app/` 为前缀：

| 切片 | 入口与拟新增模块 | 责任 |
| --- | --- | --- |
| 输入与界面 | `repository/SessionRepository.kt`、`ui/SessionDetailScreen.kt`、`MainActivity.kt`；新增 `ui/StudyPlanScreen.kt` | 原子读取课堂快照；新增分析入口、上传同意页、结果/题目/计划页面；延续现有中英文字案机制 |
| 编排 | 新增 `ai/StudyAgent.kt`、`StudySkillRouter.kt`、`StudyContracts.kt` | 固定阶段、取消、输入指纹、结构化校验；UI 不直接拼接 prompt |
| 网络 | 新增 `ai/StudyAgentClient.kt`，独立轻量后端目录 `study-agent-server/` | Android 仅调用 HTTPS 代理；服务端管理供应商密钥、验证请求和结构化响应、额度与超时 |
| 学习记录 | 新增 `ai/StudyResultStore.kt` | MVP 使用私有目录按课堂保存小型原子 JSON，不先修改原 Room v6；管理缓存、答题次数、任务状态和删除 |

拟定输入：`schemaVersion`、`requestId`、课堂内容指纹 `sourceHash`、带 ID/时间戳的最终转写、选中的疑问/注释、语言、复习期限、每天可用分钟数。设备内课堂 ID 可只在本地映射，不向供应商暴露。长课先按段落切片并预估长度；超上限须提示用户缩小范围，禁止无提示截断再称为「整课总结」。片段视为资料，不执行其中的指令。

拟定结果：`schemaVersion`、`sourceHash`、`skillVersion`、`summary`、`knowledgePoints[]`、`quiz[]`；本地衍生 `reviewTasks[]`、`attempts[]`。知识点有稳定 ID、原文 segment ID 和 evidence 文本；题目有 knowledgePoint ID、单选选项、唯一正确项、解析、evidence；任务包含日期、预计分钟数、知识点和调整原因。答题记录以题目版本和 attempt ID 去重，重复点击不能重复计分。

客户端必须验证类型、数量、ID 关联、答案范围、证据是否来自用户选中的原文；无依据结论显示为待核实或拒绝入库，不补造证据。题目事实正确性仍需人工抽查，结构校验不能替代内容审核。首版结果中的知识点 ID 在同一结果版本内保持稳定，重新分析创建新版本，旧题尝试不错误归入新题。

快照在一致事务内读取，网络调用在事务外进行；写入前复核当前内容指纹。追加笔记、修改输入后旧结果标记过期；课堂已删除则丢弃迟到响应。课堂删除联动删除分析文件，存储失败提示用户；不使用破坏性迁移、不把 AI 摘要写回原转写。

网络初始约束：单次调用总超时 60 秒，失败不自动重试；每次运行限制输入/输出长度及调用次数，具体 token/费用上限待选服务后确定。供应商密钥只放服务端环境/私有配置，不进 APK、Git 或日志。服务端还需独立可撤销的试用访问控制、限流和总额度；仅「把密钥藏到服务器」不能防盗刷。课堂文字默认不留服务端日志；真实材料上传和付费须另行获授权。本轮不部署、不付费、不上传课堂内容。
